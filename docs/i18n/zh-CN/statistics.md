# 统计和提供商用量

Statistics 汇总受支持的提供商 CLI 实际发出的用量数据。它帮助回答哪些会话、配置文件、项目和提供商消耗了模型 token；它不是计费账本，也不会虚构缺失值。

## 数字的含义

对于 Codex，ThreadCells 会记录 rollout 遥测中可用的累计提供商原生计数器：

- 输入 token；
- 缓存输入 token；
- 输出 token；
- 推理 token；
- 总 token。

缓存输入仍会单独显示。它不会被悄然再次计为新的输入。提供商未报告的指标将显示为**未报告**，而不是误导性的零。

默认表格省略缓存写入 token，因为当前没有适配器将其公开为有意义且受支持的指标。规范化 API 保留了一个可选的兼容性字段，以便未来的适配器可以在无需数据库迁移的情况下提供真实支持。

仅当适配器提供受支持且权威的值时，才会显示提供商积分、价格和成本信息。ThreadCells 不会根据 token 总数估算账单。

## 用量何时出现

用量会在实时会话运行时收集，并持久化存储。会话无需在为 Statistics 贡献数据前被删除、退役或清理。已完成但仍保留的会话会继续计入。

Codex 会发出累计快照。ThreadCells 会为这些快照创建检查点并更新同一规范用量记录，因此轮询、重启、重放或恢复不会对相同 token 重复计数。

## 阅读页面

先查看全局总计，然后使用维度表按终端、会话、项目、提供商或配置文件定位用量。总计与详情视图使用相同的规范化记录。

一个调查示例：

1. 注意到全局输出 token 增加。
2. 打开会话维度，识别产生该用量的会话。
3. 比较其项目、提供商和配置文件。
4. 打开 Agents，检查相应的终端和持久结果。

## 历史数据

仅当保留的提供商原生证据可确定性地匹配到某个 ThreadCells 会话时，升级才可能恢复历史用量。来源数据含糊或缺失时，其状态仍为未知。修复操作具有幂等性：再次运行不得创建重复记录。

旧数据库中可能仍保留旧版尽力而为的终端解析，以供追溯来源。一旦存在精确的提供商原生记录，该精确记录就会在可见总计中取代旧版近似值。

## 故障排除

- **缺少实时会话：**刷新页面，确认提供商支持用量收集，并确认服务账户仍能读取提供商 rollout。
- **字段显示未报告：**提供商没有提供该指标。不要将其理解为零。
- **重启后总计看似重复：**比较会话和终端维度，并保留数据库用于诊断；重放应更新检查点，而不是插入第二个累计总计。
- **计费不一致：**请以提供商自身计费系统作为计费权威。ThreadCells 报告的是运行遥测。

有关容量而非 token 核算，请参阅[容量和资源模型](RESOURCE_MODEL.md)。
