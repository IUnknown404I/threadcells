# Web UI を使う

Web UI は、ThreadCells を見るオペレーターのライブビューです。ループバックリスナー向けに設計されており、ブラウザーでもインストール済みの基本的な PWA としても通常どおり機能します。インストールしても、オフラインの運用動作や新しい認証境界が追加されることはありません。

![セッション、エージェント、ワークフローの密な要約を備えたライブ ThreadCells Home](/media/screenshots/threadcells-home.webp)

## 主な領域

- **Home** は、すべての端末を読み込まずに、永続的なセッションとエージェントの履歴、現在のアクティビティ、オーナーの注意、First/Last/Total の状態カウントを要約します。
- **Agents** は、端末、プロファイル／プロバイダーの識別情報、実行状態、ワークフロー状態、永続的な結果を対象に、Sessions、Statuses、Profiles のビューを提供します。
- **Flows** は、繰り返し実行されるエージェントスケジュールを作成、有効化、無効化、確認、手動実行します。結果のエージェントとワークフローのライフサイクルは Agents に表示されます。
- **Statistics** は、作り上げた指標を使わず、プロバイダー報告の使用量を表示します。
- **Settings** には、General、Orchestration Capacity、Profiles、Providers、Housekeeping、インストール全体の Telegram 通知、About があります。
- **Docs** は、実行中ビルドにパッケージされた公開許可リスト付きドキュメントを提供します。
- **Spawn Agent** は、プロジェクト、プロバイダー、プロファイルから新しいセッションを開始します。
- **Add Agent** は、選択中の正確なセッションライフタイム内に別の端末を開始します。同じ名前を共有する別の履歴セッションには参加しません。

直接 URL がサポートされています。ブラウザー履歴は、選択した Settings および Docs ページを保持するはずです。

## 通常の運用ループ

1. Home で現在のセッション／ワークフローのアクティビティを確認し、Settings でホストの健全性、ディスク負荷、利用可能な容量を確認します。
2. Spawn Agent を使い、選択したプロバイダーが準備済みであることを確認します。
3. Agents で新しいセッションを監視します。
4. 繰り返しスケジュールには Flows を使います。起動したエージェントは Agents で追跡します。
5. 子を退役させる前に、永続的な結果を読んで取り込みます。
6. Statistics を使って、プロバイダー報告の使用量を理解します。

状態ラベルは永続的なコントロールプレーンの事実に由来します。**Processing** はターンがアクティブであることを示し、**Ready** はプロバイダーランタイムが生存しており本当にアイドルであることを示します。Queued ラベルは、プロバイダー容量の枯渇、子の退役バリア、一般的なワークフロー継続を区別します。オーナーゲートのバッジはカテゴリのままですが、展開した Owner Decision パネルには具体的な永続理由が表示されます。

アクティブなセッションと履歴セッションは、別々の永続的ライフタイムのままです。履歴セッションを削除しても、その正確な適格ライフタイムだけが削除されます。終了済み端末の削除も、クリーンアップ前に正確なランタイム識別情報、書き込みリース、ワークフロー／結果保護、セッション関係を確認します。曖昧またはアクティブな状態は保護されたままです。

## 保護された設定

機密性の高い変更は、一つの **Unlock operator changes** コントロールを共有します。未設定、無効、ロック、アンロック、期限切れの状態はそれぞれ異なります。シークレットの正確な最小長は 5 文字で、デフォルトの認証済みセッションは 5 分間です。

UI はアンロック時だけシークレットを送信し、直ちに消去して、ブラウザーの永続ストレージやエクスポートに置きません。容量、特権的なプロファイル／プロバイダー変更、Telegram 設定／テスト、Housekeeping 実行、該当するオーナー起動は、サーバーセッションなしではロックされたままです。

検証子を安全に準備するには、[オペレーター認可](OPERATOR_AUTHORIZATION.md)に従ってください。

## プロバイダーとプロファイルの選択

プロバイダーラベルは、**Built-in adapter**、**CLI ready**、**CLI not installed**、**Authentication required**、**Installed but unhealthy**、**Readiness unverified** を区別します。Spawn は利用不可と証明されたプロバイダーだけを無効にし、Settings と同じサーバー preflight を使います。

プロファイルは、検索可能な組み込み／カスタムの検出と解決済みプレビューを優先します。生の成果物の import/export は、意図的に Advanced に置かれています。例外的なオーナー XHigh プロファイルを選ぶと権限警告が表示され、別個の許可経路が必要になります。

## Telegram 通知

Settings → Telegram は、プロジェクトとは独立して一つのインストール全体の宛先を設定します。bot token は UI では write-only です。接続とテストメッセージの操作は明示的で、別の確認済み clear 操作により認証情報を削除して配信を無効にします。有効な配信は、最上位の完了、オーナー注意ゲート、予期しない最上位端末失敗だけを対象とし、永続的な重複抑制と fail-open 配信を備えます。[Telegram 通知](TELEGRAM_NOTIFICATIONS.md)を参照してください。

## Statistics

Statistics は、永続的なプロバイダーテレメトリーが利用可能になり次第、アクティブ、完了、保持中で未削除のセッションを含めます。キャッシュ済み入力と推論出力は別々のままです。利用できないフィールドは **Not reported** と表示されます。[Statistics とプロバイダー使用量](STATISTICS.md)を参照してください。

## Docs リーダー

Docs ナビゲーションは学習の流れごとにグループ化され、検索可能で、広い画面ではページ内アウトラインが付きます。前へ／次へリンクは公開されたマニフェスト順に従います。リーダーが公開するのはパッケージ済みの許可リスト付き Markdown だけで、任意のファイルシステムブラウザーや編集エンドポイントはありません。

## Full Output

Full Output は、ANSI/VT 制御シーケンスと端末カーソル操作を除去してから、人間が確認できるよう保持されたプロバイダーテキストを表示します。サニタイズにより表示制御が可視履歴を書き換えることを防ぎますが、プロバイダーテキストを再解釈、実行、保証するものではありません。

## アプリとしてインストールする

サポート対象の Chromium ブラウザーでは、ブラウザーのインストール操作から ThreadCells をインストールできます。マニフェストは ThreadCells のブランディングを使い、スタンドアロン表示モードで開きます。iOS では **Add to Home Screen** を使えます。

オペレーターアクセスがブラウザー認証情報で保護されている場合、マニフェストと関連する同一オリジンリクエストは同じ認証境界を使います。クロスオリジンアクセスは明示的に信頼された origin に限定されます。PWA メタデータはオペレーターまたはリモートアクセス制御を回避しません。

控えめな service worker は、不変でフィンガープリント付きの静的アセットだけをキャッシュします。HTML ナビゲーション、API、オペレーター認可、エージェント、セッション、ワークフロー、結果、Statistics、端末、WebSocket、変更操作をキャッシュしません。サーバーが利用できない場合、インストール済みアプリは古い運用状態を表示せず、実際のネットワーク失敗を報告します。

新しい不変ビルドは、通常のブラウザー service-worker 更新ライフサイクルを通じて、古いフィンガープリント付きアセットを置き換えます。ThreadCells はオペレーターを古いオフラインシェルに留めません。

## レスポンシブ表示とキーボード利用

主要ナビゲーション、Docs、Settings、テーブル、端末コントロールは、スマートフォン、タブレット、デスクトップ幅をサポートします。広い運用テーブルは、値を読めないほど縮小するのではなく、狭い画面では横スクロールします。

スマートフォンでは、各 Home セッションヘッダーに専用の名前行と別のメタデータ／操作行があります。エージェントカードは常に正規の一列リストを使い、List/Grid セレクターは非表示です。タブレットとデスクトップのレイアウトでは、List/Grid の選択を保持します。

通常の Tab/Shift-Tab ナビゲーションと可視のフォーカスインジケーターを使います。Docs のコードブロックは横スクロールし、コピーコントロールを提供します。端末のキーボード動作はプロバイダー固有のままです。タッチスクロールが端末入力を注入してはいけません。

## アクセス境界

通常の UI と Docs は、一般的なユーザーログインを提供しません。ThreadCells はループバック上に保ってください。[リモートアクセス](REMOTE_ACCESS.md)の SSH トンネルまたは認証済み Caddy/Authelia プロキシを使い、ポート 9889 を直接公開してはいけません。
