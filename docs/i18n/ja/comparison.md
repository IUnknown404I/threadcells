# ThreadCells の位置付け

ThreadCells は、ネイティブのコーディングエージェント CLI をすでに評価しており、1 台のマシンで複数をより明確に運用したい開発者向けです。

## 個別のターミナルウィンドウとの比較

個別の tmux シェルは単純ですが、プロファイル／プロバイダー ID、管理対象 writer の所有権、容量許可、workflow の親子関係、永続的な子結果、またはオペレーターゲートを自動的に記録しません。ThreadCells はネイティブターミナルを維持しつつ、これらの運用記録を追加します。

## ホスト型エージェントプラットフォームとの比較

ThreadCells はセルフホスト型で、loopback-first です。リポジトリ、ターミナル、調整データベースはオペレーターのホストに残ります。その代わり、オペレーターがインストール、プロバイダー認証、バックアップ、パッチ適用、リソースサイジング、リモートアクセス保護を担います。

## コンテナまたはセキュリティサンドボックスとの比較

ThreadCells はそのようなものではありません。管理対象 worktree と権限ポリシーは調整上のミスを減らしますが、ネイティブプロバイダープロセスをオペレーティングシステムアカウントから分離しません。

## 自律型ソフトウェアファクトリーとの比較

ThreadCells は、境界のある委任、検査可能なターミナル、明示的な結果、オーナー判断、および証拠に裏付けられた完了を重視します。レビューなしにエージェントが任意のソフトウェアを出荷できるとは約束しません。

ThreadCells は AWS Labs CLI Agent Orchestrator の独立した downstream であり、必要に応じて互換性のある `cao` internals を保持します。OpenHands や Hermes のような無関係なエージェント製品の drop-in replacement ではありません。ホスト型マルチテナンシーや広範なプラットフォーム抽象化ではなく、ローカルのネイティブ CLI 運用と永続的な supervisor/worker 制御のために選択してください。
