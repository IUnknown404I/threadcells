# Zu ThreadCells beitragen

Vielen Dank, dass Sie ThreadCells verbessern helfen. Meldungen und Pull Requests sind willkommen, wenn sie fokussiert, umsetzbar und öffentlich sicher besprechbar sind.

## Den richtigen Weg wählen

- **Fehler:** Verwenden Sie das [Fehlerberichtsformular](https://github.com/IUnknown404I/threadcells/issues/new?template=bug.yml) mit Reproduktionsschritten oder dauerhafter Evidenz.
- **Erweiterung:** Verwenden Sie das [Funktionswunschformular](https://github.com/IUnknown404I/threadcells/issues/new?template=feature.yml) und beginnen Sie mit dem Problem oder Anwendungsfall.
- **Dokumentation:** Verwenden Sie das [Dokumentationsberichtsformular](https://github.com/IUnknown404I/threadcells/issues/new?template=docs.yml) für fehlende, veraltete oder unklare öffentliche Anleitung.
- **Fragen und Fehlerbehebung:** Sehen Sie in die [Dokumentation](https://iunknown404i.github.io/threadcells/docs/) und [Troubleshooting](docs/TROUBLESHOOTING.md), und fragen Sie dann in [Discussions Q&A](https://github.com/IUnknown404I/threadcells/discussions/categories/q-a).
- **Frühe Ideen:** Beginnen Sie mit dem Problem oder Anwendungsfall in [Discussions Ideas](https://github.com/IUnknown404I/threadcells/discussions/categories/ideas). Verschieben Sie es erst in ein Issue, wenn das Ergebnis nach der Issue-Richtlinie konkret und umsetzbar ist.
- **Setups und Anwendungsfälle:** Teilen Sie Workflows, Integrationen, Screenshots und Erfahrungen in [Show and tell](https://github.com/IUnknown404I/threadcells/discussions/categories/show-and-tell).
- **Sicherheit:** Eröffnen Sie kein öffentliches Issue. Folgen Sie [SECURITY.md](SECURITY.md) und melden Sie es privat.

Durchsuchen Sie vorhandene [Discussions](https://github.com/IUnknown404I/threadcells/discussions) oder offene und geschlossene [Issues](https://github.com/IUnknown404I/threadcells/issues), bevor Sie einen neuen Thread oder Bericht beginnen. Die ausführlichen Regeln zu Issue-Eignung, Evidenz, Triage und Offenlegung stehen in der kanonischen [Issue-Richtlinie](docs/ISSUES.md).

## Pull Requests

Vor dem Öffnen eines Pull Requests:

1. Beginnen Sie vom neuesten `main` und prüfen Sie auf überlappende Issues und Pull Requests.
2. Halten Sie die Änderung begrenzt; besprechen Sie umfangreiche Arbeit zuerst in einem Issue.
3. Ergänzen oder aktualisieren Sie gezielte Tests und Dokumentation, wenn sich das Verhalten ändert.
4. Führen Sie die relevanten lokalen Prüfungen aus und führen Sie deren Ergebnisse im Pull Request auf.
5. Nehmen Sie keine Credentials, privaten Pfade, personenbezogenen Daten, Produktionszustände oder Terminaltranskripte auf.
6. Verwenden Sie eine klare Commit-Nachricht und reagieren Sie auf Review- und CI-Feedback.

ThreadCells ist eine unabhängige technische Vorschau. Halten Sie die öffentliche Zusammenarbeit respektvoll und auf Informationen beschränkt, die sicher offengelegt werden können. Informationen zur Beitragslizenzierung finden Sie in [LICENSE](LICENSE).
