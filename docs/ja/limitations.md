# 現在の制限事項

ThreadCells は、1 台の Linux ホスト上でコーディングエージェントを信頼できる形でローカル運用することに焦点を当てた技術プレビューです。ここに挙げる境界は意図的な製品上の事実であり、未実装のエンタープライズ機能に関する約束ではありません。

## プラットフォームと規模

- サポート対象ホストのベースラインは Ubuntu/Debian Linux です。
- 1 つのローカルコントロールプレーンと SQLite データベースが、1 台のホストで小規模なフリートを調整します。
- 容量制限は競合を減らしますが、厳格な CPU／メモリーコンテナを作成したり、スループットを保証したりしません。
- 非常に大規模なマルチホスト、高可用性、または水平スケールのインストールは、現在の契約の対象外です。

## 信頼と分離

- ネイティブエージェントは runtime ユーザーのオペレーティングシステムアクセスで実行されます。
- worktree は Git チェックアウトを分離しますが、ファイルシステムやネットワークのセキュリティを分離するものではありません。
- プロバイダーアダプターは信頼された実行可能パッケージです。
- このシステムは、敵対的なマルチテナンシーや信頼できない公開サインアップ向けには設計されていません。

## Web アクセス

- 通常の UI には、組み込みの一般ユーザーログインがありません。
- 外部の認証付き HTTPS プロキシで保護しない限り、サーバーは loopback-only のままにする必要があります。
- オペレーター認可は機密設定を保護しますが、外部アクセス制御の代替ではありません。
- インストール可能な PWA はネットワーク依存であり、オフラインのエージェント制御を提供しません。

## プロバイダーとテレメトリー

- 組み込みアダプターの可用性は、CLI のインストール、互換性、プロバイダー認証により異なります。
- 一部のプロバイダーは認証状態を非対話的に報告できません。
- 使用量フィールドは、プロバイダーが正確なテレメトリーを提供する場合にのみ存在します。
- Statistics は運用テレメトリーであり、請求明細ではありません。過去の不明値は不明のままです。

## 復旧と自動化

- 復旧は永続状態を外部の tmux／プロバイダープロセスと照合しますが、非冪等な外部コマンドを可逆にすることはできません。
- バックアップと復元にはオペレーターの規律が必要であり、事前に練習すべきです。
- ハウスキーピングでは、あいまいなアーティファクトを意図的にそのまま残します。
- Full Cleanup は最大限の証明済み安全な回収であり、すべての大容量ファイルが不要であるという保証ではありません。全エージェントがアイドルであることが必要で、曖昧なツール／バックアップ／worktree を保持する場合があり、非アクティブリリースのクリーンアップ成功後は意図的にローカルリリースロールバックを残しません。
- 公開およびリモートリリースの自動化は、通常のローカルデプロイの一部ではありません。

まず非重要リポジトリで ThreadCells を評価し、検証済みバックアップを維持し、重大な操作の前にエージェント出力を確認してください。
