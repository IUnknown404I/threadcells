# ここから始める: ThreadCells とは？

ThreadCells は、Linux マシン上で複数のコーディングエージェントを一つの協調ワークフローとして実行するセルフホスト型システムです。エージェントに実際の端末と Git worktree を与え、モデルターンをまたぐオープンなミッションを進め続け、容量、書き込みアクセス、保護された変更、最終結果をオペレーターが制御できるようにします。

Git、SSH、コマンドラインのコーディングエージェントを使えるなら、始めるための背景知識は十分です。有用な作業を開始する前に、ThreadCells の内部アーキテクチャを理解する必要はありません。

## なぜ使うのか？

一つのコーディングエージェント端末は理解しやすいものです。端末が複数になると難しくなります。二つのエージェントが同じブランチを編集したり、ビルドでメモリを使い切ったり、レビューを回収する前にスーパーバイザーが消えたり、端末の完了が依頼されたミッションの完了を必ずしも意味しなかったりします。

ThreadCells はこれらの関係を明示し、自身の実行環境を維持します。特に次のような場合に役立ちます。

- 長時間動くエージェントを可視化し、再接続可能にしておく。
- 並列ワーカーに別々の管理済み worktree を与える。
- スーパーバイザーに実装とレビューを委任させる。
- 結果と Inbox メッセージを、端末間で手作業でコピーせずに返す。
- プロバイダーのターンや通常の再起動をまたいで、一つの論理的なミッションを続ける。
- モデルターン、アクティブな作業、ホスト負荷の高いタスクを個別に制限する。
- 端末が終了した後も結果を保持する。
- ホスト負荷を監視し、使い捨て可能な ThreadCells ランタイム、ログ、キャッシュ、ビルド、リリースの残骸を安全にクリーンアップする。
- 機密性の高い、または曖昧な手順の前にオーナー判断を必須にする。

ThreadCells は、自分で制御するホスト上の信頼できる一人のオペレーターまたは小規模な信頼できるチーム向けに設計されています。敵対的なマルチテナントサンドボックスではありません。

## 基本の流れ

```text
Create a session and choose a project and agent
        ↓
Give the agent or supervisor the job
        ↓
Watch the coordinated workflow and host state
        ↓
ThreadCells continues eligible work across model turns
        ↓
Step in only for an explicit owner decision or final review
```

エージェントは引き続きネイティブのプロバイダー CLI で動作します。ThreadCells は周囲の作業を協調させるもので、プロバイダーを置き換えるものではありません。Housekeeping は、所有権と適格性を証明できる候補だけを回収しつつ、進行中の作業、永続状態、バックアップ、現行／リカバリーリリースを保護します。これにより ThreadCells の残骸を手作業で見守る負担は減りますが、物理ホストが決して故障しないという約束ではありません。

## 最初の一時間でできること

1. [クイックセットアップ](../QUICK_SETUP.md)に従って、ローカル候補をビルド・検証します。
2. 各手順の理由を知りたい、または前提条件の支援が必要なら、[インストール](INSTALLATION.md)を使います。
3. [最初のプロジェクトとエージェント](FIRST_AGENT.md)に従います。
4. 一度エージェントを動かした後で、[基本概念](CONCEPTS.md)を読みます。
5. 別のマシンを使う前に、[リモートアクセス](REMOTE_ACCESS.md)から安全な方法を選びます。

その後、[Providers](PROVIDERS.md)、[Profiles](PROFILES.md)、[ワークフローと永続的な結果](WORKFLOWS_AND_RESULTS.md)で主要な運用モデルを説明します。[運用](OPERATIONS.md)では、インストールを健全に保つ定期チェックを扱います。

## ThreadCells が行わないこと

ThreadCells の worktree は書き込みを整理しますが、エージェントをホストからサンドボックス化するものではありません。ThreadCells は Web UI に一般的なログイン保護も追加しません。サーバーはループバック専用に保ち、リモートアクセスには SSH 転送または認証済みリバースプロキシを使ってください。

現在のリリースは技術プレビューです。貴重なリポジトリをエージェント管理下に置く前に、[セキュリティモデル](SECURITY_MODEL.md)と[制限事項](LIMITATIONS.md)を読んでください。
