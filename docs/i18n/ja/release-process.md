# リリースプロセス

クリーンでコミット済みのツリーから、`scripts/build_local_candidate.py --output <new-directory>` を使用して隔離されたローカル候補をビルドします。これは生成された Docs/UI とローカル wheel をパッケージ化します。`SHA256SUMS` を検証し、`candidate-manifest.json`、`sbom.cdx.json`、`EVIDENCE.md` を確認したうえで、新しいプレフィックスを用いた文書化済みのクリーンインストールを実行します。タグ、リモートブランチ、パッケージ、イメージ、または公開リリースの公開は、通常の実装作業ではありません。

## リリースチェックリスト

1. 実装を完了し、独立した統合レビューを 1 回実施します。
2. 対象を絞ったテストに加え、意味のある本番ビルド／ブラウザの輪郭チェックを 1 回実行します。
3. `git diff --check` と公開対象サーフェスの監査を実行します。
4. 承認された正確なツリーをコミットします。
5. 未コミットの変更がある worktree ではなく、そのコミットから候補をビルドします。
6. マニフェスト、チェックサム、SBOM、ビルド ID、Docs ルート、およびクリーンインストールを検証します。
7. ローカル昇格の前に、従来の runtime とデータベースバックアップを保存します。
8. 公開 push、タグ、パッケージ、イメージ、またはリリースはすべて、オーナーが承認する個別の作業として扱います。

リリース証跡はテストおよびパッケージ化された内容を示しますが、それ自体で公開を承認したり、すべての依存関係のライセンス／セキュリティ特性を保証したりするものではありません。

## OCI リリース配布

承認済みの公開 alpha リリースには、`ghcr.io/iunknown404i/threadcells-release-bundle` に公開 OCI 配布アーティファクトもあります。これには、検証済みリリースアーカイブ、Python wheel、チェックサム一覧、候補マニフェスト、SBOM、および正確な一つのリリースタグとソースリビジョンのためのリリースバンドルメタデータが含まれます。

このパッケージは配布バンドルであり、Docker イメージでもサポート対象のコンテナデプロイ環境でもありません。チェックサムを検証した後は、通常の候補インストールおよびデプロイ手順を使用してください。OCI アーティファクトを ThreadCells サービスとして実行しようとしないでください。

`.github/workflows/publish-release-bundle.yml` は、承認された GitHub Release 時または明示的なバックフィル dispatch により公開します。既存のドラフトではない prerelease を持つ注釈付き `v0.X.Y-alpha.N` タグのみを受け入れ、タグ付けされた正確なソースを再ビルドして検証し、不一致のバージョンタグの置換を拒否し、更新するのは `latest-alpha` のみです。ThreadCells は技術プレビュー中に無修飾の `latest` タグを公開しません。

## バージョンラインの規約

ThreadCells は通常の SemVer prerelease 順序に従います。alpha プレビュー中、`0.1.X` は意味のある製品、信頼性、または文書のイテレーションを示し、`alpha.N` は本当に必要な場合にその同じイテレーション内で追加する公開を示します。

- `v0.1.0-alpha.1` は最初の公開 alpha でした。
- `v0.1.0-alpha.2` は不変の公開済み技術プレビューです。
- `v0.2.0-alpha.1` は統合された多言語・信頼性リリースラインです。
- 同じリリースライン内で後続の公開を行う場合は alpha シーケンスのみを増やし、新たな製品輪郭ではセマンティックバージョンを意図的に増やします。

既存のタグを移動してはいけません。リポジトリガバナンスの変更だけではバージョン更新やリリースの契機になりません。次の意味のある実装輪郭が公開準備できたときに限り、すべての正規バージョン表記サーフェスをまとめて更新します。
