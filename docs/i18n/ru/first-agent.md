# Ваш первый проект и агент

В этом руководстве запускается один намеренно небольшой агент и показано, где найти его терминал и результат. Сначала завершите [Quick setup](../QUICK_SETUP.md) и оставьте сервер ThreadCells запущенным.

## 1. Подготовьте безопасный репозиторий

Для первого запуска используйте одноразовый или чистый Git-репозиторий. ThreadCells определяет проект по его репозиторию и может создавать рядом с ним управляемые worktree.

```bash
mkdir -p /tmp/threadcells-first-project
cd /tmp/threadcells-first-project
git init
printf '# First project\n' > README.md
git add README.md
git commit -m 'Create first project'
```

Ожидаемый результат: `git status --short` ничего не выводит. Чистое начало упрощает проверку изменений агента.

## 2. Откройте ThreadCells

Откройте `http://127.0.0.1:9889` на машине, где запущен ThreadCells. Если хост удалённый, сначала настройте SSH-туннель, описанный в [Удалённом доступе](REMOTE_ACCESS.md).

Откройте **Spawn Agent**, выберите репозиторий в качестве проекта и установленный провайдер. Провайдер с отметкой **CLI not installed** не может запуститься; если ожидаемый провайдер недоступен, см. [Провайдеры](PROVIDERS.md).

Для этой первой задачи выберите профиль исполнителя общего назначения. Введите ограниченный запрос, например:

```text
Add a short Usage section to README.md. Do not change any other file.
Run git diff --check and report the changed file.
```

Запустите агента.

## 3. Наблюдайте за терминалом

Новый агент появится в разделе **Agents**. Его терминал — настоящая сессия tmux, поэтому нативный вывод провайдера остаётся видимым и к нему можно переподключиться. ThreadCells записывает проект, профиль, провайдера и идентификатор сессии, связанные с этим терминалом.

Ожидаемый результат: статус меняется со starting на running, появляется вывод провайдера, а доступная ёмкость учитывает одно активное выполнение провайдера, пока модель генерирует ответ.

Если агент не запускается, проверьте метку доступности провайдера и карточки ёмкости. В [Устранении неполадок](TROUBLESHOOTING.md) есть проверки по симптомам.

## 4. Проверьте работу

Когда агент завершит работу, проверьте его сохранённый результат и изменения в репозитории. Терминал, достигший финального сообщения провайдера, — это свидетельство, но не разрешение на слияние, публикацию или развёртывание.

```bash
cd /tmp/threadcells-first-project
git status --short
git diff -- README.md
```

Если агент работал в управляемом Git worktree, используйте показанный ThreadCells путь, а не путь исходного репозитория. Git worktree изолирует параллельных исполнителей записи, пока их commits намеренно не будут согласованы.

## 5. Попробуйте координацию

Когда работа одного исполнителя станет понятна, запустите профиль координатора для другой небольшой задачи. Попросите его назначить одну задачу реализации и одну независимую проверку. Связь должна выглядеть так:

```text
Owner
  └── Supervisor
        ├── Developer
        └── Reviewer
              ↓
        Durable results return to the supervisor
```

Координатор остаётся ответственным за включение этих результатов и завершение рабочего процесса верхнего уровня. Завершение исполнителя не закрывает задачу координатора.
