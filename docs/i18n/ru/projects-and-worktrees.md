# Проекты и управляемые worktree

Проект ThreadCells — это зарегистрированный Git-репозиторий. Он даёт сессиям, профилям, статистике и workflow устойчивое место принадлежности. ThreadCells не делает репозиторий безопасным, просто зарегистрировав его, поэтому начинайте с чистого статуса и понимайте предоставляемую границу записи.

## Регистрация проекта

Используйте селектор проектов в Spawn Agent, чтобы выбрать существующий репозиторий или добавить репозиторий через поддерживаемый элемент управления проектом. Используйте абсолютный канонический путь и убедитесь, что runtime user ThreadCells может его читать.

Перед первым агентом:

```bash
git -C /path/to/project status --short
git -C /path/to/project worktree list
```

Ожидаемый результат: вы можете отличить уже существующие изменения и worktree от всего, что ThreadCells создаст позднее. Существующая незафиксированная работа принадлежит оператору; агенты не должны её отбрасывать.

## Зачем нужны управляемые worktree

Два автора в одном checkout могут перезаписывать правки друг друга, даже если их запросы не связаны. Управляемый Git worktree даёт каждому ограниченному автору собственный checkout и ветку, используя общую объектную базу репозитория.

```text
Canonical repository
  ├── operator checkout
  ├── supervisor context
  ├── developer worktree
  └── reviewer worktree or read-only context
```

ThreadCells записывает эту связь, а не рассматривает временные каталоги как анонимные. Это делает очистку и атрибуцию результатов безопаснее.

## Полномочия на запись

Только контекст с полномочиями на запись должен изменять управляемый worktree. Проверяющие могут изучать diff и выполнять безопасные проверки, не становясь неучтённым вторым автором.

Не редактируйте управляемый worktree вручную, пока его агент активен. Если необходимо аварийное вмешательство, сначала остановите автора или скоординируйте его, а затем зафиксируйте, что изменилось.

## Возврат работы

Сохранённый результат должен называть изменённые файлы и проверки, но Git остаётся источником истины для кода. Перед слиянием или cherry-pick в обычном процессе репозитория проверьте статус, diff и commits worktree.

ThreadCells не выдаёт полномочия на публикацию. Успешный результат исполнителя не разрешает push, tagging, deployment или переписывание истории.

## Очистка

Housekeeping удаляет управляемый worktree только если может доказать, что worktree больше не защищён активным терминалом, workflow, writer lease или невключённым результатом. Неизвестное владение закрывается с отказом.

Если использование диска высоко, сначала спланируйте Housekeeping. Не удаляйте каталог worktree напрямую: это может оставить метаданные Git и состояние ThreadCells несогласованными.

## Частые ошибки

- Начинать с грязного репозитория, не зафиксировав существующие изменения.
- Давать двум агентам полномочия на запись в один checkout.
- Считать worktree security sandbox.
- Удалять worktree до включения его результата и commits.
- Предполагать, что управляемая ветка автоматически слита или отправлена.

См. [Рабочие процессы и сохранённые результаты](WORKFLOWS_AND_RESULTS.md), чтобы узнать, как результаты worktree поступают координатору.
