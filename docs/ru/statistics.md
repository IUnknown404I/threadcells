# Statistics и использование провайдеров

Statistics суммирует использование, которое действительно выдают поддерживаемые CLI провайдеров. Оно помогает ответить, какие сессии, профили, проекты и провайдеры израсходовали токены модели; это не бухгалтерская книга и не выдумывает отсутствующие значения.

## Что означают числа

Для Codex ThreadCells записывает накопительные нативные счётчики провайдера, доступные в телеметрии rollout:

- входные токены;
- кэшированные входные токены;
- выходные токены;
- токены рассуждения;
- всего токенов.

Кэшированный ввод остаётся видимым отдельно. Он не добавляется повторно как новый ввод. Метрика, которую провайдер не сообщил, отображается как **Не сообщается**, а не как вводящий в заблуждение ноль.

Таблицы по умолчанию не показывают токены записи в кэш, поскольку ни один текущий адаптер не предоставляет их как осмысленную поддерживаемую метрику. Нормализованный API сохраняет необязательное поле совместимости, чтобы будущий адаптер мог добавить правдивую поддержку без миграции базы данных.

Сведения о кредите, цене и стоимости провайдера показываются только когда адаптер предоставляет поддерживаемое авторитетное значение. ThreadCells не оценивает счета по общему числу токенов.

## Когда появляется использование

Использование собирается во время работы живой сессии и сохраняется надёжно. Сессию не требуется удалять, выводить из эксплуатации или очищать, чтобы она учитывалась в Statistics. Завершённые, но сохранённые сессии продолжают учитываться.

Codex выдаёт накопительные снимки. ThreadCells создаёт для них контрольные точки и обновляет одну и ту же каноническую запись использования, поэтому опрос, перезапуск, повтор или возобновление не учитывают одни и те же токены дважды.

## Чтение страницы

Начните с глобальных итогов, затем используйте таблицы измерений, чтобы найти использование по терминалу, сессии, проекту, провайдеру или профилю. Итоги используют те же нормализованные записи, что и подробные представления.

Пример исследования:

1. Заметьте рост глобального числа выходных токенов.
2. Откройте измерение сессий, чтобы определить вносящую вклад сессию.
3. Сравните её проект, провайдера и профиль.
4. Откройте Agents, чтобы изучить соответствующий терминал и сохранённый результат.

## Исторические данные

Обновления могут восстановить историческое использование, только когда сохранённые нативные свидетельства провайдера можно детерминированно сопоставить с сессией ThreadCells. Неоднозначные или отсутствующие исходные данные остаются неизвестными. Исправление идемпотентно: повторный запуск не должен создать дублирующую запись.

Устаревший best-effort разбор терминала может оставаться в старых базах данных для происхождения. Когда существует точная нативная запись провайдера, она заменяет устаревшее приближение в видимых итогах.

## Устранение неполадок

- **Живая сессия отсутствует:** обновите страницу, проверьте, поддерживает ли провайдер сбор использования, и убедитесь, что rollout провайдера остаётся доступен для чтения service account.
- **Поле показывает «Не сообщается»:** провайдер не предоставил эту метрику. Не считайте её нулём.
- **Итоги выглядят дублированными после перезапуска:** сравните измерения сессий и терминалов и сохраните базу данных для диагностики; повтор должен обновлять контрольную точку, а не вставлять второй накопительный итог.
- **Биллинг отличается:** используйте собственную систему биллинга провайдера как источник истины. ThreadCells сообщает операционную телеметрию.

О ёмкости, а не учёте токенов, см. [Модель ёмкости и ресурсов](RESOURCE_MODEL.md).
