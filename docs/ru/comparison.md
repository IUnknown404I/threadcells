# Место ThreadCells

ThreadCells предназначен для разработчиков, которые уже ценят нативные CLI агентов программирования, но хотят понятнее управлять несколькими из них на одной машине.

## В сравнении с отдельными окнами терминала

Отдельные оболочки tmux просты, но они не записывают автоматически идентичность профиля/провайдера, владение управляемым writer, допуск по ёмкости, родственные связи рабочих процессов, устойчивые результаты дочерних задач или ворота оператора. ThreadCells сохраняет нативные терминалы, добавляя эти операционные записи.

## В сравнении с хостинговой платформой агентов

ThreadCells разворачивается самостоятельно и ориентирован прежде всего на loopback. Репозитории, терминалы и база данных координации остаются на хосте оператора. Взамен оператор отвечает за установку, аутентификацию провайдера, резервное копирование, обновления, выделение ресурсов и защиту удалённого доступа.

## В сравнении с контейнерами или песочницами безопасности

ThreadCells не является ни тем, ни другим. Управляемые worktree и политики полномочий уменьшают ошибки координации, но не изолируют нативные процессы провайдера от учётной записи операционной системы.

## В сравнении с автономными фабриками ПО

ThreadCells делает акцент на ограниченном делегировании, доступных для проверки терминалах, явных результатах, решениях owner и завершении, подкреплённом свидетельствами. Он не обещает, что агенты смогут поставлять произвольное ПО без проверки.

ThreadCells — независимый downstream AWS Labs CLI Agent Orchestrator и сохраняет совместимые внутренние компоненты `cao` там, где это необходимо. Он не является прямой заменой несвязанных продуктов для агентов, таких как OpenHands или Hermes. Выбирайте его для локальной работы с нативными CLI и устойчивого управления supervisor/worker, а не для хостинговой мультитенантности или широкой абстракции платформы.
