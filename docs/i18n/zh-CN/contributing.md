# 为 ThreadCells 做贡献

感谢你帮助改进 ThreadCells。我们欢迎聚焦、可执行且适合公开讨论的报告和拉取请求。

## 选择正确渠道

- **缺陷：**使用带有复现步骤或持久证据的[缺陷报告表单](https://github.com/IUnknown404I/threadcells/issues/new?template=bug.yml)。
- **增强：**使用[功能请求表单](https://github.com/IUnknown404I/threadcells/issues/new?template=feature.yml)，并从问题或使用场景开始。
- **文档：**使用[文档报告表单](https://github.com/IUnknown404I/threadcells/issues/new?template=docs.yml)报告缺失、过时或不清晰的公开指南。
- **问题和故障排除：**查看[文档](https://iunknown404i.github.io/threadcells/docs/)和[故障排除](docs/TROUBLESHOOTING.md)，然后在 [Discussions Q&A](https://github.com/IUnknown404I/threadcells/discussions/categories/q-a) 中提问。
- **早期想法：**先在 [Discussions Ideas](https://github.com/IUnknown404I/threadcells/discussions/categories/ideas) 中讨论问题或使用场景。仅当结果根据 Issue 政策已具体且可执行时，才转为 Issue。
- **部署配置和使用场景：**在 [Show and tell](https://github.com/IUnknown404I/threadcells/discussions/categories/show-and-tell) 中分享工作流、集成、截图和经验。
- **安全：**不要创建公开 Issue。请遵循 [SECURITY.md](SECURITY.md) 并私下报告。

在创建新讨论串或报告前，先搜索现有[Discussions](https://github.com/IUnknown404I/threadcells/discussions)或公开和已关闭的 [Issues](https://github.com/IUnknown404I/threadcells/issues)。详细的 Issue 资格、证据、分诊和披露规则载于规范的 [Issue 政策](docs/ISSUES.md)。

## 拉取请求

在创建拉取请求前：

1. 从最新 `main` 开始，并检查是否有重叠的 Issue 和拉取请求。
2. 保持变更有边界；重大工作请先在 Issue 中讨论。
3. 行为变化时，添加或更新聚焦测试和文档。
4. 运行相关本地检查，并在拉取请求中列出结果。
5. 不要包含凭据、私有路径、个人数据、生产状态或终端记录。
6. 使用清晰的提交消息，并响应审查和 CI 反馈。

ThreadCells 是独立的技术预览。请保持公开协作尊重他人，并且仅限于可安全披露的信息。贡献许可请参阅 [LICENSE](LICENSE)。
