# Быстрая настройка ThreadCells

Это самый быстрый поддерживаемый путь от копии исходного кода до локального сервера ThreadCells. Он собирает неизменяемый локальный кандидат, проверяет его содержимое, устанавливает из текущего репозитория и принимает подключения только через loopback.

Для предварительных требований, объяснений сбоев и установки службы используйте полное [руководство по установке](docs/INSTALLATION.md).

## 1. Проверьте хост

Сейчас ThreadCells рассчитан на Ubuntu/Debian Linux с Python 3, Git, tmux, Node.js/npm для сборки веб-интерфейса и CLI хотя бы одного поддерживаемого провайдера. Основной протестированный провайдер — Codex.

Из корня репозитория:

```bash
python3 --version
git --version
tmux -V
node --version
npm --version
```

## 2. Соберите и проверьте кандидат

```bash
python3 scripts/build_local_candidate.py --output "$PWD/threadcells-candidate"
candidate="$PWD/threadcells-candidate/threadcells-0.3.0a3-local"
python3 scripts/verify_local_candidate.py --candidate "$candidate"
```

Ожидаемый результат: проверка успешно проходит для манифеста, файлов, контрольных сумм и упакованного веб-интерфейса кандидата. Кандидат — это самодостаточный каталог в форме релиза; его неизменяемость позволяет однозначно определить запущенную сборку и упрощает rollback.

## 3. Сначала просмотр, затем установка

```bash
"$candidate/scripts/install-threadcells.sh" --source "$candidate" --dry-run
"$candidate/scripts/install-threadcells.sh" --source "$candidate" --prefix "$PWD/.threadcells"
```

Ожидаемый результат: предварительный запуск объясняет свои цели, ничего не меняя, затем установка создаёт `.threadcells` с окружением Python и командами ThreadCells.

## 4. Запустите диагностику

```bash
"$PWD/.threadcells/venv/bin/threadcells" doctor
```

Устраните не пройденные обязательные проверки до запуска агентов. Необязательный провайдер может отсутствовать; в UI он будет отмечен как **CLI not installed**.

## 5. Запустите сервер

```bash
"$PWD/.threadcells/venv/bin/threadcells-server" --host 127.0.0.1 --port 9889
```

Откройте `http://127.0.0.1:9889`.

Ожидаемый результат: загружается Home, в Settings → About показывается идентификатор запущенной сборки, а эта документация доступна в Docs.

Для первого запуска оставьте host и port строго доступными только через loopback. Для другой машины не меняйте listener на `0.0.0.0`; используйте [Удалённый доступ](docs/REMOTE_ACCESS.md).

Операционная модель намеренно краткая: создайте session, выберите агента или координатора, дайте ему задачу, наблюдайте за рабочим процессом и вмешивайтесь только для явного решения владельца или финальной проверки. Одно лишь завершение провайдера не закрывает открытый рабочий процесс.

## 6. Начните полезную работу

Следуйте [Ваш первый проект и агент](docs/FIRST_AGENT.md). Входящий в состав проекта [безопасный стартовый пример](examples/threadcells-starter/README.md) — это также ограниченное упражнение с координатором, разработчиком и проверяющим, которое ничего не публикует и не меняет службы.

## Остановка и возобновление

Остановите сервер в активном терминале с помощью `Ctrl-C`. Терминалы агентов работают поверх tmux и могут пережить отключение браузера, но не считайте, что прерванный сервер завершил их рабочие процессы. Перезапустите тот же установленный `threadcells-server`, откройте Agents и проверьте их текущее состояние и сохранённые результаты.
